# Глоссарий - объяснение терминов для начинающего программиста

Этот файл объясняет простыми словами все термины, которые встречаются в проекте
«Сервис новостей» (лабораторные работы №1-3). Каждый термин - с коротким
«человеческим» объяснением и примером из кода, где это уместно.

---

## 1. Базовые вещи, без которых никак

### Программа, процесс, сервер
* **Программа** - набор инструкций, которые выполняет компьютер.
* **Процесс** - запущенная (работающая) программа.
* **Сервер** - программа, которая «слушает» сеть и отвечает на запросы других
  программ. В нашем проекте сервер - это класс `WebAppServer`, который ждёт
  HTTP-запросы и отдаёт ответы.
* **Клиент** - программа (например, браузер), которая отправляет запросы серверу.

### Исходный код и сборка
* **Исходный код (source code)** - то, что пишет программист (наши `.java` файлы).
* **Компилятор** - программа, которая переводит исходный код в исполняемый вид
  (байт-код).
* **Байт-код** - «промежуточный» язык, в который компилируется Java. Он
  выполняется виртуальной машиной Java.
* **Сборка (build)** - процесс превращения исходного кода в готовый артефакт
  (jar-файл): компиляция + упаковка.

### JDK и JRE
* **JRE (Java Runtime Environment)** - среда **запуска**: умеет только выполнять
  готовые программы, но не компилировать.
* **JDK (Java Development Kit)** - комплект **разработчика**: включает JRE и
  компилятор (`javac`). Нужен, чтобы собирать проект.
* **JAVA_HOME** - переменная окружения, указывающая, где установлен JDK. Без неё
  Maven может «не найти» компилятор.

## 2. Язык Java

| Термин | Объяснение |
|--------|------------|
| **Класс** | «Чертёж», по которому создаются объекты. Например, класс `NewsBO` описывает, из чего состоит новость. |
| **Объект (экземпляр)** | Конкретная «вещь», созданная по классу. `new NewsBO(...)` создаёт один объект-новость. |
| **Поле (field)** | Переменная внутри класса. У `NewsBO` есть поле `title` (заголовок). |
| **Метод** | Функция внутри класса - действие, которое объект умеет выполнять. `news.publish()` - «опубликовать». |
| **Сигнатура метода** | «Паспорт» метода: имя + список параметров. |
| **Параметр** | Входное значение, которое метод получает. |
| **Возвращаемое значение** | Результат, который метод отдаёт обратно (`return ...`). |
| **Конструктор** | Особый метод, который вызывается при `new` и настраивает новый объект. |
| **Геттер / сеттер** | Методы `getName()` / `setName(...)` - чтение и запись поля. |
| **Интерфейс** | «Договор»: список методов, которые класс обязан реализовать. `IPublishable` требует метод `publish()`. |
| **Абстрактный класс** | Класс-«заготовка», который нельзя создать напрямую (`new`), а только наследовать. У нас это `PersonBO`. |
| **Наследование** | Когда класс «расширяет» другой (`JournalistBO extends UserBO`). Класс-наследник получает поля и методы родителя. |
| **Перечисление (enum)** | Тип с фиксированным набором значений. `NewsStatus` - это `DRAFT`, `PUBLISHED`, `EDITED`, `ARCHIVED`, `DELETED`. |
| **Пакет (package)** | Папка, в которой лежат классы (`controller.news`). Строка `import ...` подключает чужой пакет. |
| **Аннотация** | Пометка `@...` над классом или методом. Например, `@Path("/reader")` говорит библиотеке, что класс обрабатывает адрес `/reader`. |
| **Javadoc** | Комментарий `/** ... */`, который описывает класс или метод. |

## 3. Сборка проекта: Maven

| Термин | Объяснение |
|--------|------------|
| **Maven** | Инструмент сборки: скачивает библиотеки и компилирует проект. |

## 4. Веб и REST

| Термин | Объяснение |
|--------|------------|
| **HTTP** | Протокол (язык общения) между клиентом и сервером. |
| **HTTP-метод** | «Глагол» запроса: `GET` - получить, `POST` - создать, `PUT` - изменить, `DELETE` - удалить. |
| **URL** | Адрес ресурса: `http://localhost:8093/reader/news/all`. |
| **Хост** | Имя компьютера (`localhost` = «этот компьютер»). |
| **Порт** | «Дверь» на сервере, за которой слушает программа (у нас 8091/8092/8093). |
| **Запрос / ответ** | Клиент шлёт запрос, сервер возвращает ответ (код + данные). |
| **Статус-код** | Число в ответе: `200` - всё ок, `201` - создано, `400` - неверный запрос, `401` - нет доступа, `404` - не найдено. |
| **Endpoint** | Конкретный адрес + метод, которые что-то делают. `GET /reader/news/all` - endpoint. |
| **Path-параметр** | Часть адреса-значение: в `/reader/news/1` число `1` - это `{id}` (`@PathParam`). |
| **Query-параметр** | Значение после `?`: `?keywords=метро` (`@QueryParam`). |
| **REST API** | Набор endpoint'ов для работы с данными поверх HTTP. |
| **RESTEasy** | Библиотека (реализация JAX-RS), которая превращает наши классы с аннотациями `@Path`/`@GET` в рабочий REST API. |
| **JAX-RS** | Стандарт, описывающий, как писать REST API на Java (набор аннотаций). |
| **Undertow** | Встроенный веб-сервер: принимает HTTP-запросы и передаёт их в RESTEasy. |
| **Встроенный (embedded) сервер** | Сервер, который запускается прямо из нашей программы (`main`), а не отдельным приложением. |
| **CORS** | Правила, разрешающие браузеру со страницы одного адреса обращаться к серверу на другом адресе. |

## 5. Данные: JSON, DTO, BO

| Термин | Объяснение |
|--------|------------|
| **JSON** | Текстовый формат данных: `{"id":1,"title":"Новость"}`. Удобен для обмена между сервером и браузером. |
| **Сериализация** | Превращение объекта Java в JSON (для отправки клиенту). |
| **Десериализация** | Обратное превращение JSON в объект Java (когда клиент шлёт данные). |
| **Jackson** | Библиотека, которая делает сериализацию/десериализацию автоматически. |
| **MessageBodyWriter / Reader** | Внутренние «преобразователи» JAX-RS: Writer пишет объект в ответ, Reader читает из запроса. |
| **DTO (Data Transfer Object)** | «Плоский» класс без логики, только для передачи данных клиенту. Клиент не должен видеть внутренние объекты сервера. |
| **BO (Business Object)** | Бизнес-объект: класс предметной области с данными **и** логикой (методами). Живёт только на сервере. |
| **Facade (Фасад)** | Класс-«посредник», который прячет сложную внутреннюю логику и даёт простые методы. |

**Зачем DTO и BO разделяют?** Бизнес-объекты содержат лишние/внутренние данные
(пароли, служебные поля) и логику. Клиенту это не нужно. DTO - «выжимка» только
тех полей, которые можно показывать. Фасад превращает BO в DTO.

## 6. Паттерны проектирования (в нашем проекте)

| Паттерн | Суть простыми словами | Где в проекте |
|---------|----------------------|----------------|
| **Singleton (Одиночка)** | Гарантирует, что объект существует в одном экземпляре. | `SingletonAPI` (один набор API), `FacadeController.getInstance()` (одни данные). |
| **Facade (Фасад)** | Один класс-«вход» прячет сложную внутреннюю кухню. | `FacadeController` - API не знает про BO и хранилища. |
| **DTO** | Отдельный класс только для передачи данных наружу. | Пакет `view.api.dto`. |
| **MVC** | Разделение на «данные» (Model), «логику» (Controller), «интерфейс» (View). | Пакеты `model`, `controller`, `view`. |

## 7. UML (диаграммы, которые лежат в `docs/`)

| Термин | Объяснение |
|--------|------------|
| **UML** | Язык схем, чтобы рисовать устройство программы до написания кода. |
| **Диаграмма классов** | Показывает классы, их поля/методы и связи. Источник наших BO. |
| **Актёр (actor)** | «Человечек» - роль пользователя системы (Гость, Пользователь, Журналист, Администратор). |
| **Use case (прецедент)** | Действие, которое актёр может выполнить («Искать новости», «Администрирование»). |
| **Диаграмма состояний** | Показывает, как объект меняет состояние (Draft → Published → Deleted). |
| **Диаграмма коммуникаций** | Показывает, как объекты пересылают друг другу сообщения для одной операции. |
| **Диаграмма компонентов** | Показывает модули и библиотеки системы. |
| **Диаграмма развёртывания** | Показывает, на каких машинах/контейнерах работает система. |
| **Наследование на диаграмме** | Стрелка `<|--`: `User <|-- Admin` значит «Admin наследует User». |
| **Композиция** | Связь `*--`: «часть не может жить без целого» (комментарий - часть новости). |
| **Агрегация** | Связь `o--`: более слабая «состоит из» (категория и новости). |
| **Кратность (0..*, 1)** | Сколько объектов участвует в связи: `1 -- 0..*` = «один к нулю-или-многим». |

## 8. Как всё связано (шпаргалка по проекту)

```
Браузер (клиент)
   │  HTTP-запрос (GET /reader/news/all)
   ▼
Undertow (встроенный сервер)  - принимает запрос
   ▼
RESTEasy + JAX-RS             - по аннотациям @Path/@GET находит нужный метод
   ▼
ReaderAPI / CreatorAPI / AdminAPI  - контроллеры (слой view)
   ▼
FacadeController              - фасад (слой controller): BO <-> DTO
   ▼
NewsBO, UserBO, ... + InMemoryStore  - бизнес-объекты и хранилище (слой model)
   ▼
Ответ: Jackson превращает DTO в JSON → обратно в браузер
```

## 9. Словарик одной строкой

* **artifact** - файл-результат сборки (jar).
* **API** - «интерфейс» программы для других программ; список методов/адресов.
* **деплой (deploy)** - «развернуть» приложение на сервере.
* **заглушка (stub)** - временная реализация, которая ничего не делает, а возвращает тестовый ответ.
* **контекст (context path)** - префикс адреса, под которым работает приложение.
* **репозиторий** - хранилище данных (в проекте - `InMemoryStore`).
* **статический файл** - файл, отдаваемый как есть (HTML, картинки), без обработки.
* **fetch** - команда в JavaScript, которая отправляет HTTP-запрос из браузера.
